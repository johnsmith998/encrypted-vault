# important file git · 开发指南

> 面向：继续开发、上传 GitHub、在 Mac / Windows 上自测  
> 更新：2026-06-07

---

## 一、你刚才遇到的错误是什么意思？

终端显示：

```text
未找到保险库，请先创建：
  bash scripts/macos/create-vault.sh
```

**不是脚本坏了**，而是：

1. Git 版项目**默认**去找这条路径：
   ```
   ~/Library/Application Support/LocalPrefs/local.prefs.backup.sparsebundle
   ```
2. 你真正的私人保险库在 **移动硬盘** 上（私人版 `important file` 里配置过），例如：
   ```
   /Volumes/WD Elements/iphone 12/local.prefs.backup.sparsebundle
   ```
3. Git 版是**新项目**，还没有 `vault.location`，也没在默认路径建过库 → 所以 `mount-vault.sh` 找不到文件。

**结论：** 要先告诉 Git 版「保险库在哪」，或者在新位置**创建一个测试库**。

## 二、两条路：选一条即可

### 路线 A：继续用你已有的私人保险库（推荐日常）

适合：数据已经在 WD Elements 上，不想重复建库。

**步骤（按顺序复制执行）：**

```bash
# 1. 进入 Git 版项目
cd "/Users/xy/Downloads/项目/important file git"

# 2. 插上移动硬盘 WD Elements（必须，否则路径不存在）

# 3. 把保险库路径告诉 Git 版（只写在本机 vault.location，不会上传 GitHub）
bash scripts/macos/set-vault-location.sh "/Volumes/WD Elements/iphone 12/local.prefs.backup.sparsebundle"

# 4. 确认路径
bash scripts/macos/set-vault-location.sh

# 5. 打开
bash scripts/macos/mount-vault.sh
```

若第 3 步报错「路径不存在」，说明硬盘没挂好，或 `.sparsebundle` 不在该文件夹——先在访达里确认文件真实位置，再改路径。

**注意：**

- `vault.location` 已在 `.gitignore`，**不会**被 commit。
- Git 版与私人版可以**共用同一个** `.sparsebundle`，只是「遥控器」（脚本）在两个文件夹里各有一份。
- 私人版命令是 `bash scripts/mount-vault.sh`；Git 版是 `bash scripts/macos/mount-vault.sh`（多了 `macos/`）。

---

### 路线 B：为开源项目单独建一个「演示 / 测试库」

适合：上传 GitHub 后给别人看流程；或不想动 WD Elements 上的真实数据。

```bash
cd "/Users/xy/Downloads/项目/important file git"

# 可选：指定测试库位置（例如项目外的临时目录）
bash scripts/macos/set-vault-location.sh "$HOME/Desktop/demo-vault-test/local.prefs.backup.sparsebundle"

# 创建（只需一次，会要求设密码）
bash scripts/macos/create-vault.sh 5g

# 打开
bash scripts/macos/mount-vault.sh
```

测试库与私人 WD Elements 库**完全独立**，密码也可不同。

```bash
cd "/Users/xy/Downloads/项目/important file git"

# 查看 / 设置路径

bash scripts/macos/set-vault-location.sh "/你的路径/xxx.sparsebundle"
```

```bash

```

## 五、Windows 端开发 / 自测清单

在 Windows 电脑上（或虚拟机）：

1. 安装 [VeraCrypt](https://www.veracrypt.fr/en/Downloads.html)
2. 克隆或拷贝本仓库
3. PowerShell：

```powershell
cd "C:\path\to\important file git"

# 若策略拦截脚本
powershell -ExecutionPolicy Bypass -File .\scripts\windows\create-vault.ps1

# 正常情况
.\scripts\windows\create-vault.ps1
.\scripts\windows\mount-vault.ps1
.\scripts\windows\unmount-vault.ps1
```

4. 改路径 / 盘符：

```powershell
.\scripts\windows\set-vault-location.ps1 "$env:USERPROFILE\Documents\LocalVault\local.prefs.backup.hc"
.\scripts\windows\set-drive-letter.ps1 W
```

**重要：** Windows 的 `.hc` 与 macOS 的 `.sparsebundle` **不能互相打开**。跨机器要带文件，需各平台各建库，或未来改 Cryptomator 方案（见 `docs/mobile.md`）。

## 六、上传 GitHub 前检查（必做）

在 Git 版项目根目录执行：

```bash
cd "/Users/xy/Downloads/项目/important file git"

# 1. 确认没有敏感文件
git status   # 若尚未 init，先 git init

# 2. 不应出现以下内容：
#    - vault.location
#    - *.sparsebundle / *.hc / *.dmg
#    - 个人备忘录、真实硬盘路径写死在文档里
```

### 建议首次提交包含

- [x] `README.md`、`LICENSE`、`.gitignore`
- [x] `scripts/macos/`、`scripts/windows/`
- [x] `config/vault.location.example`
- [x] `docs/`（含本开发指南）
- [ ] **不要**提交 `vault.location`、保险库文件、`.DS_Store`

### 初始化 Git 与推送（示例）

```bash
cd "/Users/xy/Downloads/项目/important file git"
git init
git add .
git status    # 再确认一遍没有 sparsebundle / vault.location
git commit -m "Initial commit: encrypted vault scripts for macOS and Windows"
```

推送前在本项目 `.env.local` 配置（若已安装 PAT 推送脚本）：

```env
GITHUB_REPO=你的用户名/仓库名
GITHUB_TOKEN=ghp_xxxx
```

然后：

```bash
npm run git:push
# 或按 ~/.cursor/templates/README-git-push.md 安装脚本后推送
```

## 八、开发时禁止提交的内容

| 文件 / 内容 | 原因 |
|-------------|------|
| `vault.location` | 含个人绝对路径 |
| `*.sparsebundle`、`*.hc` | 加密容器本体（即使用户数据安全也不该进 Git） |
| 密码、PAT、`GITHUB_TOKEN` | 安全 |
| `备忘录.md`、私人换机笔记 | 非产品文档 |
| 硬编码 `/Users/xy/`、`WD Elements` | 改用 `config/*.example` 与文档示例 |

## 九、与 AI / Cursor 协作约定

1. 开发 Git 版时，工作区打开 **`important file git`**，不要混进私人版未脱敏文件。
2. 不要让 AI 读取**已挂载**的 `/Volumes/LocalPrefs` 内容。
3. 改脚本后在本机跑一遍：`bash -n scripts/macos/*.sh`（语法检查）。
4. 问 AI 时可以说：「按 `开发指南.md` 第七节 P1 继续做 GitHub 上传准备」。

## 十、故障排查

| 现象 | 处理 |
|------|------|
| 未找到保险库 | 执行 `set-vault-location.sh` 指到真实 `.sparsebundle`；或 `create-vault.sh` 新建 |
| 脚本「没反应」/ 卡住 | 先看是否在等「按回车」或密码输入（终端里输入，光标不动是正常的）；勿在管道里跑脚本 |
| `hdiutil: create failed - 不适当的设备ioctl` | macOS 15+ 上 GUI 密码框可能失败；Git 版已改用终端 `-stdinpass`，请更新脚本后重试 |
| WD Elements 路径无效 | 先插硬盘；访达确认 `.sparsebundle` 完整路径 |
| 资源忙，无法 detach | 关闭 Preview/访达里打开的文件；再 `unmount-vault.sh` |
| 密码忘了 | 无法恢复；只能新建空库 |
| Windows 找不到 VeraCrypt | 安装后确认路径在 `Program Files\VeraCrypt\` |
| PowerShell 无法运行脚本 | `-ExecutionPolicy Bypass -File ...` |
| Git 版与私人版混淆 | Mac 脚本路径：Git 版带 `macos/` 子目录 |

## 十一、两句话记住

**已有私人库：** 插硬盘 → `set-vault-location.sh` 指路径 → `mount-vault.sh`

**从零开源演示：** `create-vault.sh` → `mount-vault.sh` → 开发完 `git init` 上传（不带 vault.location）

## 十二、复制到新项目时

若你之后在别的目录重新克隆 / 复制本仓库：

1. 复制整个 `important file git` 文件夹，或 `git clone` 你的 GitHub 仓库。
2. **不要**复制私人版的 `vault.location` 到公开仓库；在新机器上按第二节重新 `set-vault-location`。
3. 本文件 `开发指南.md` 随仓库一起走，作为维护手册。

如有新进展，可在本文「第七节」自行勾选完成的任务，或在 `docs/` 下追加 `CHANGELOG.md`。
